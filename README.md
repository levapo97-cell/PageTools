# DevToolSDK

Independent, hands-on reviews and head-to-head comparisons of the SaaS and developer tools teams
actually deploy — CI/CD, infrastructure, hosting, containers, databases and frameworks.

Built with **Astro 7** (static output), **Tailwind CSS 4**, **TypeScript** and content
collections. No client-side framework runtime: the only JavaScript that ships is the theme
toggle, the mobile nav and the two forms.

---

## Quick start

```bash
npm ci                 # install
cp .env.example .env   # configure the domain (and ads, later)
npm run dev            # http://localhost:4321
```

| Script | What it does |
| ------ | ------------ |
| `npm run dev` | Dev server with hot reload |
| `npm run build` | Static build into `dist/` |
| `npm run preview` | Serve the built `dist/` locally |
| `npm run check` | `astro check` — TypeScript + content collection schemas |
| `npm run sync` | Regenerate `.astro/types.d.ts` after schema changes |

Node 22.12 or newer is required.

## Design system

Colors, typography and spacing are CSS custom properties in `src/styles/global.css`.

- **Brand:** `#0066CC` (primary) and `#004499` (dark), exposed as a full `brand-50…950` scale.
- **Semantic tokens:** `surface`, `surface-muted`, `surface-raised`, `border-subtle`,
  `border-strong`, `ink`, `ink-muted`, `accent`. Each is redefined under `.dark`, so every
  utility (`bg-surface`, `text-ink`, …) flips with the theme automatically.
- **Dark mode:** class-based, via `@custom-variant dark (&:where(.dark, .dark *))`. The stored
  preference is applied by an inline script in `Head.astro` *before* first paint, so there is no
  flash of the wrong theme.
- **Typography:** Inter from Google Fonts, with a system-font stack fallback.

To rebrand, change the `--color-brand-*` values in `@theme` and the `--accent*` values in `:root`
/ `.dark`. Nothing else hardcodes a color.

## Environment variables

Copy `.env.example` to `.env`. Everything is `PUBLIC_`-prefixed and inlined into the build — do
not put secrets here.

| Variable | Required | Purpose |
| -------- | -------- | ------- |
| `PUBLIC_SITE_URL` | yes | Canonical origin. Drives canonical tags, OG, sitemap, RSS, robots. |
| `PUBLIC_ADSENSE_CLIENT` | no | AdSense publisher id (`ca-pub-…`). |
| `PUBLIC_ADSENSE_ENABLED` | no | `true` to emit ad markup. Keep unset in preview environments. |
| `PUBLIC_CONTACT_ENDPOINT` | no | Contact form POST target. Falls back to `mailto:`. |
| `PUBLIC_NEWSLETTER_ENDPOINT` | no | Newsletter POST target. |

## SEO

Handled centrally so pages only supply content:

- **Meta tags** — `src/components/Head.astro`: title, description, canonical, keywords, robots.
- **Open Graph + Twitter cards** — including `article:published_time` / `article:modified_time`.
- **Schema.org** — `src/lib/schema.ts` builds one `@graph` per page: `Organization` and `WebSite`
  on every page, plus `Article`, one `Review` node per reviewed tool, `BreadcrumbList`,
  `CollectionPage`, `AboutPage` or `ContactPage` as appropriate.
- **Sitemap** — `@astrojs/sitemap`, excludes `/404`.
- **RSS** — `/rss.xml`, reviews and articles merged and sorted by date.
- **robots.txt** — generated per environment; preview hosts are fully disallowed.

## Adding content

See [`docs/CONTENT.md`](docs/CONTENT.md) for the full frontmatter reference, and
[`docs/templates/`](docs/templates) for copy-paste starting points.

Short version: drop a Markdown file into `src/content/reviews/` or `src/content/articles/`. The
filename becomes the slug. `npm run check` validates the frontmatter against the Zod schema and
fails the build if something is missing.

## Monetisation

Google AdSense Auto Ads, plus three manually placed slots. All of it is inert until you set
`PUBLIC_ADSENSE_CLIENT` and `PUBLIC_ADSENSE_ENABLED=true` — with ads off, `<AdSlot />` renders
nothing at all, so there is no reserved empty box and no layout shift.

The policy pages AdSense requires for approval — `/privacy`, `/terms`, `/disclosure` — are
built and linked from every page's footer. `ads.txt` is generated from the publisher id rather
than hand-maintained. Before applying, fill in the real entity details in the `LEGAL` object in
`src/consts.ts`.

Full setup and the pre-approval checklist in [`docs/GOOGLE-ADS.md`](docs/GOOGLE-ADS.md).
